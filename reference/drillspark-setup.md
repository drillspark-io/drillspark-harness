# DrillSpark に繋がるか確かめる

各 skill が**開始直後に1回**参照する。オーナーが未登録・未接続のときに、代わりの手段で進めないための節。

## DrillSpark は必須。代わりの手段で進めない

このハーネスは**図を契約として扱う**。図が無ければ承認する対象が無く、
実装が何から導かれたのかも辿れない。**繋がらないなら止まる。** 特に次の2つをしない。

- **CLI に mermaid や ASCII の図を貼って図の代わりにする**（→ harness-implement〈出力の作法〉）
- **図を飛ばして `設計.md` の文章だけで実装へ進む**

止まっている状態は失敗ではない。**保留として記録すれば足りる。**
黙って別の手段に切り替えることだけが失敗で、そのときオーナーは
「図が無いまま実装された」ことに**あとから気づく**（気づけないこともある）。

## 疎通は最初に1回だけ確かめる

skill に入って最初の出力を出す前に、**読み取り専用の呼び出しを1回**流す。

```
mcp__drillspark__list_projects()
```

**工程1より前に確かめる。** 図が要るのは〈処理を作る〉だが、そこまで進んでから詰まると、
**承認ゲートを2つ通した成果（目的・処理一覧）が宙に浮く。**

繋がっていたら**何も言わずに先へ進む。** 「接続を確認しました」を報告しない —
オーナーが判断することが1つも無い報告は、承認の重みを削る。

## 症状で切り分ける

| 症状 | 何が起きているか | どうするか |
|---|---|---|
| `mcp__drillspark__*` が1つも無い／ツールが見つからない | 未接続。アカウントが無いこともある | 下の**案内**を出して止まる |
| `401` / `403` / `unauthorized` | 接続はあるが API キーが無効か期限切れ | キーの再発行を頼んで止まる |
| 接頭辞が違う（`mcp__claude_ai_DrillSpark__*` など） | **繋がっている。**事前許可が効かず毎回確認が出るだけ | **止めない。**そのまま進める。確認を減らしたいならサーバ名を `drillspark` に揃えるよう伝える |
| 特定のプロジェクトだけ `404` | 権限違いか ID 違い。**接続の問題ではない** | ID を確かめる。**接続の案内を出さない** |

**接続の問題と、それ以外を混ぜない。** 何でも「繋ぎ直してください」と返すと、
オーナーは繋ぎ直しても直らないものを繋ぎ直すことになる。

## 案内する文面

**【人間の実行】接続はオーナーにしかできない。** `AskUserQuestion` で出す
（テキストで番号付きの質問を並べない → harness-implement〈出力の作法〉）。

1. **アカウント** — https://drillspark.io/ で作る
2. **接続** — 2通りある
   - **Claude Code** — ダッシュボード（https://drillspark.io/dashboard）で API キー（`dsk_…`）を発行し、
     MCP サーバ `https://drillspark.io/api/mcp/mcp` を `type: http` で追加して
     `Authorization: Bearer <キー>` を付ける
   - **Claude.ai Web / Claude Desktop** — 設定のコネクタから OAuth で連携する
3. **サーバ名は `drillspark`。** skill と agent は `mcp__drillspark__*` で事前許可を宣言しているので、
   この名前のときだけ許可が効く。違う名前でも**動く**（毎回確認が出るだけ）
4. **確認** — `/mcp` に出るかを見る。セッションの途中で繋いだ場合は**再起動が要る**

出典: https://drillspark.io/ja/docs/mcp

**API キーを `設計.md`・図の備考・ログ・コミットに書かない。** 貼られても復唱しない。
キーは接続の設定にだけ置く。

## 上限とエスカレーション先

**案内は1回まで。** 出したらそこで止まる。直らなくても同じ案内を繰り返さない —
オーナーが作業して戻ってくるまで、こちらにできることは無い。

**エスカレーション先はオーナー。** 中止するときは、
何が起きたか（症状の行）と、どこまで進んだかを `設計.md` の保留に残してから止まる。
