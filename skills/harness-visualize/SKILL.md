# harness-visualize — 処理1つを1枚の HTML にする

両環境で共通の工程・承認・成果物の意味は [ワークフロー契約](../../reference/workflow-contract.md) を読む。

**これは処理であって工程ではない。** `目的を考える → … → 評価する →（改善する）` の連鎖には入らない。
`設計.md` を持つハーネスなら、**処理ごとに・いつでも**単独で呼べる。標準は〈評価する〉の直後。

**処理**＝ハーネスが持つ独立したワークフロー。**工程**＝その処理の中身。
可視化するのは**処理1つ分**で、複数の処理のノードを1枚に混ぜない。
ただし1枚の冒頭に**ハーネス全体の地図**（処理一覧・共有部品・介入点の総数）を持つ — 処理の粒度で書き、ノードは持たない。

1枚で答える問いは2つ。**この処理のどの作業が、どのファイルのどの部分で、何の仕組みとして効いているか。**
**このハーネス全体はどんな設計か（処理はいくつで、何を共有しているか）。**

**1枚はモデルが書かない。** 図の解析・表・Mermaid 原文・抜粋・設計システム・両方向リンクは
同梱の生成スクリプト `scripts/harness-view-build.js` が決定論で組み立てる。モデルが書くのは
**対応づけ（`map.json`）だけ**で、図は DrillSpark の応答をそのまま写す（`diagrams.json`）。
1枚は 100 KB を超えるので、モデルに1回の Write で書かせると出なかった（headless で4回、15〜45分）。

## やらないこと（ここが濁ると役割が壊れる）

- **判定しない。** GO / NO-GO も合否も書かない。判定は `harness-evaluator` の仕事。
  評価結果があるなら**転記するだけ**で、可視化側で採点し直さない
  （判定を持たせると、生成側が自分の合格線を描くことになる）
- **直さない。** ズレを見つけても直さない。直すのは `harness-improve`
- **図を書き換えない。** 読むだけ。`update_diagram` はこのスキルの許可ツールに無い
- **推測で埋めない。** 入力に無いものは「無し」「未記録」と描く
- **HTML を直接 Write しない。Edit もしない。** 1枚は生成スクリプトが書く（柵が Edit と手書きを止める）

## 入力（物差しは `docs/harness/<ハーネス名>/` のファイルだけ）

| 入力 | 出所 | 無いとき |
|---|---|---|
| 設計 | 索引 `docs/harness/<ハーネス名>/設計.md` と、描く処理の `処理/<処理名>/` | **これが無ければ実行しない。**止めてオーナーへ報告する |
| 図 | `処理/<処理名>/図.md` が指す DrillSpark（`get_project` が返す `content.diagrams`）、または渡された `.mmd` | 「図 無し」と描き、工程は設計の記述から並べる。**ただし下を読む** |
| 実測 | `処理/<処理名>/実装.md`／`評価/<日付>.md`／**明示的に渡された記録ファイル** | 全工程を `設計のみ` と描き、そう明記する |
| 実装先 | `処理/<処理名>/実装.md` の**実物**を優先し、無ければ `合格条件.md` の成果物一覧。工程がどのファイルのどこになったか・何の仕組みか | その工程を `未記録` と描く |
| 全体 | `設計.md` の処理一覧（状態列）／`統合.md`（1つにまとめたもの・介入点の総数）／**他の処理の `実装.md` 2節**（作ったものの一覧だけ） | 統合が無ければ「統合 未実施」と書き、在るものだけで地図を描く |

**この処理だけは他の処理のフォルダを読んでよい。** 描く側が前の処理を見ない分離は作図の混入を防ぐためのもので、
可視化は描かないので当たらない（統合と同じ理由）。読むのは全体の地図に要る一覧だけで、他の処理のノードは持ち込まない。

**「図 無し」と「図が取れない」を混同しない。** `設計.md` が DrillSpark のプロジェクトを参照しているのに
`mcp__drillspark__*` が使えないなら、それは**図が無いのではなく繋がっていない**。
`設計.md` に図の参照があるときは `list_projects()`（接頭辞は `mcp__drillspark__` か `mcp__claude_ai_DrillSpark__`） を1回流して確かめ、
繋がらなければ**止めて案内する** → [`reference/drillspark-setup.md`](../../reference/drillspark-setup.md)。
黙って「図 無し」と描くと、**在る図を無いことにした1枚**が残り、次の人はそれを現状として読む。

**実測ファイルのパスを決め打ちしない。** `実行記録.md` のような名前を実行役は発明しがちだが、
`reference/設計.md.template` は定義していない。渡されたものを読む。
**渡されなければ聞かずに `設計のみ` で描く**（人間の介入点を増やさない。
承認を連打させる設計は承認そのものを無力化する）。

**止まるのは `設計.md` が無いときだけ**。物差しが無ければ描けるものが無い。

**設計側のファイルに無いものは描かない。**〈評価する〉と同じ物差しにしておかないと、
可視化だけが独自の事実を持ち始める。

## 手順

1. **入力を集める。** 上の表の5行。どれが手に入り、どれが無いかを先に確定させる。
   **`設計.md` が無ければここで止めてオーナーへ報告する**。
   **読むのはこの5行と、`skills/harness-implement/MAPPING.md` の 2.1節・3.1節だけ。**
   プラグインの `scripts/`・`tests/`・他の skill 本文を読まない（1枚の形は生成スクリプトが持っている）。
   `tests/run.sh` を走らせない。ブラウザで描画確認をしない — 1枚の合否は lint と読み戻しで決める。
   **ファイルは1つずつ Read で読む** — まとめて `cat` すると出力が切り詰められ、読み直しになる。
   この範囲を超えて読むと、入力集めだけで時間を使い切って1枚が出ない
2. **図を写す。** `get_project` が返した `content.diagrams`（`{ "root": "flowchart …", "2": … }`）を**そのまま**
   `docs/harness/<ハーネス名>/可視化/<処理名>-<日付>.diagrams.json` に Write する。手で編集しない — 原文が正。
   図の構造（ノードID・形状・ラベル・レーン・エッジ）は生成スクリプトが機械で拾う。**LLM の読解で数え直さない。**
   取れないもの（ループ上限・エスカレーション先）だけ備考と設計から読む
3. **実測と実装先を工程へ突き合わせる。** ノード単位で `通った` / `止まった` / `設計のみ` の3値にする。
   **実測が無い工程を `通った` にしない。**「記録が無い」と「通らなかった」は違うので、
   どちらも `設計のみ` に寄せて、記録が無い旨を書く。
   あわせて**実装先（ファイル＋箇所＋仕組み）を `処理/<処理名>/実装.md` から転記する**。
   仕組みの語彙は4つ — **指示**（本文のお願い）／**確認**（`permissions.ask`・`AskUserQuestion`）／
   **柵**（hook の exit 2・`permissions.deny`）／**agent**（別コンテキストへの委譲）。
   `skills/harness-implement/MAPPING.md` 3.1節の置き場と 2.1節の介入点から降ろした、この処理の正本の語彙。
   **実ファイルを読んで埋め直さない** — 読んで書くと、可視化が設計側と違う事実を持ち始める
   （抜粋の行範囲を決めるために読むのは可。禁じているのは「対応づけを実ファイルから起こすこと」）。
   `実装.md` にも `合格条件.md` にも無ければ `未記録`。**`未記録` と「対応物が無い（`—`）」を混ぜない**
4. **ハーネス全体の地図を組む。** 処理一覧（状態・起動・成果物・介入点の内訳）、共有部品（`settings.json` の hooks と
   permissions・`CLAUDE.md`・評価基準・合格条件の置き場）、処理 × 部品の表、介入点の総数。
   材料は入力表の「全体」行だけで、**ノードの粒度には降りない**。この1枚の処理を目立たせる
5. **対応づけを `map.json` に書く。** 3 と 4 の結果と、目的・介入点・合格条件・成果物・抜粋・未完を、次節の形で
   `docs/harness/<ハーネス名>/可視化/<処理名>-<日付>.map.json` に Write する。
   図に無い成果物・統合が無いこと・評価が無いことは、`open`（未完）に書く。**無いものは書かないのではなく「無し」と書く**。
   `map.json` は Write で直接書く — 組み立て用の補助スクリプトや一時ファイルを作業ディレクトリに残さない
6. **生成スクリプトを走らせる。**

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/harness-view-build.js" docs/harness/<ハーネス名>/可視化/<処理名>-<日付>.map.json
   # exit 0 = 書いた / 2 = 入力の不備か柵に止められた（理由が stderr に出る） / 1 = 実行エラー
   ```

   同じフォルダの `.diagrams.json` を読み、`<処理名>-<日付>.html` を組み立てる。**書く前に柵**
   （`scripts/harness-view-guard.js`: 既存の1枚への上書き／回数欄の上限／view-lint の違反）を通し、落ちれば書かない。
   止められたら**直すのは `map.json` か `diagrams.json`** で、直して同じコマンドを再実行する。
   回数欄 `<!-- 直し: N/2 -->` は生成スクリプトが進める（新規 0、書き直すたびに +1）。**上限2回**を超えたら柵が書かせない —
   **止めてオーナーへ報告する**（何がどう落ちたかを添える）。直し続けない。
   実行エラー（exit 1）は入力の直しでは消えないので、直さずに報告する。
   **同じ処理・同じ日に別の1枚を出すときは上書きしない。** `<処理名>-<日付>-2.map.json` のように連番を足す
   （「既存物を書き換えない」ことが、この処理に承認ゲートを置かなくてよい根拠になっている）
7. **読み戻す。** 書かれた HTML を開き直して中身を確認する。成功メッセージを完了根拠にしない。
   対応づけの写し間違い・二重の行・空の節のような lint が見ない欠陥を見つけたら、`map.json` を直して 6 を再実行する
   （その直しも上限2回に含まれる）。**最後に置き場を伝える** — `可視化/<処理名>-<日付>.html` をブラウザで開く、と1行

## `map.json` の書き方

値の文は HTML を書いてよい（`<code>` `<strong>`。外部の読み込みは lint が落とす）。ノードIDは図と同じ綴り。

| キー | 型 | 何を書くか |
|---|---|---|
| `harness` `process` `date` | 文字列 | ハーネス名・処理名・日付（`YYYY-MM-DD`）。**必須** |
| `purpose` | 文字列 | 目的と成功指標（`設計.md` 1節の転記）。**必須** |
| `materials` `banner` | 文字列 | 副題（材料の出所）と、先頭の注意書き（実測が無い、など）。任意 |
| `titles` | `{ 図キー: 題 }` | 子図の題（root は `process` を使う）。`parent` は `{ 子: 親 }`（`"4_3": "4"`）。パンくずに使う |
| `harnessMap` | オブジェクト | `note`／`cards[]`（`name` `short` `me` `state` `start` `products` `gates`。`me: true` がこの1枚の処理）／`shared[]`（`part` `where` `cols[]` — 処理ごとの列。「無し」「書かない」「呼ばない」で始まる値は薄く出る）／`totals` |
| `nodes` | `{ ノードID: … }` | **全ノード。** `what`（何になったか。MAPPING 3節の語）／`mech`（`plea` 指示・`ask` 確認・`fence` 柵・`agent`・`none`）／`file`（相対パス。無ければ `—`）／`where`（箇所）／`src`（転記元）／`status`（`t` 通った・`s` 止まった・`d` 設計のみ・`n` 未記録）／`evidence`（実測の根拠。任意）。**必須** |
| `gates[]` | 配列 | 介入点5種を**全部**（`kind` `nodes[]` `nodesNote` `where` `mech` `status`）。無い種別も `nodes: []` で「無し」と書く。`gatesNote` に数え合わせの結果 |
| `tests` | オブジェクト | `tag`（凍結日）／`note`／`head[]`／`rows[][]`（# 条件 データ 期待 結果）／`footnote`。結果は評価レポートから転記、無ければ `未記録` |
| `products` | オブジェクト | `rows[][]`（# パス 種別 由来 実際）。由来にノードIDの配列を入れると飛べるリンクになる／`note` |
| `excerpts[]` | 配列 | 実ファイルの効いている部分。`file`（相対パス）`from` `to`（**1箇所 40 行まで**。超えると生成が止まる）`ref`（ノードID）`label`。プラグインが配るファイル（`${CLAUDE_PLUGIN_ROOT}` 配下）は抜粋せず、`nodes` の `file` にパスと役割だけ書く |
| `open[]` | 配列 | 未完。評価が無い・統合が無い・対応表が空欄、など。**無ければ「無し」の1行** |

## 生成される1枚（スクリプトが保証する契約。lint が見る）

| | |
|---|---|
| 置き場 | `docs/harness/<ハーネス名>/可視化/<処理名>-<日付>.html`（`.map.json` と同じ basename） |
| 形 | **1ファイル完結。** CSS / JS はインライン、外部読み込みゼロ（CDN も不可）。ダークテーマと `prefers-reduced-motion` に追従 |
| 回数欄 | 先頭に `<!-- 直し: N/2 -->`。生成スクリプトが進め、柵が上書きと上限を止める |
| 節 | `data-section` を9つ: `目的` `処理一覧` `工程` `介入点` `合格条件` `成果物` `ファイル→ノード` `実ファイル` `未完`（lint が必須とするのは7つ） |
| 図 | root（第一階層）は SVG。ノードは `<a href="#表の行" data-ref>` で包み、状態を枠の色と印（✓ ■ ○）で示す。凡例は「状態」「線」「形」の3群。子図は表と `<details>` の Mermaid 原文（生成行は省く） |
| 表 | 図ごとに8列（ノード／工程／状態／何になったか／仕組み／実装先ファイル／箇所／転記元）。行の `data-node-id` は全図で一意。仕組みはチップ（指示 ·／確認 ?／柵 ⊘／agent ⇢）。状態で絞り込むボタン |
| 逆引き・実ファイル | ファイル → 部分 → ノード の表。抜粋は行番号つきで、部分をクリック（Enter）すると図と表へ戻れる |
| 私的情報 | 絶対パス・UUID・メールアドレス・API キーの形は lint が落とす。**抜粋する実ファイルに入っていれば1枚は落ちる** — それは「渡せない1枚になった」と分かるということ |

**`data-node-id` はページ内で一意。** 同じノードは表の行に1回だけ。図・逆引き・抜粋から指すときは `data-ref`。
この使い分けが両方向のリンクを成立させる（生成スクリプトがそう書く。手で足さない）。

## 合格条件

**1枚の合否**は手順6の柵（書く前に lint）と手順7の読み戻しで決まる。

**このスキル自身**（生成スクリプト・lint・柵）の合格条件は、プラグイン同梱の `tests/ok-build-*.json` `tests/ok-view-*.html`
`tests/ng-view-*.html` に凍結してある。各サンプルは**期待するコードと件数**を持ち、ランナーが**終了コードだけでなくそれも照合する**。
これはプラグインの保守用で、**可視化を実行するときには走らせない**（走らせても1枚の合否は変わらない）。

```bash
bash "${CLAUDE_PLUGIN_ROOT}/tests/run.sh"   # 保守用。生成・lint・柵の期待挙動 ＋ 同梱ファイルの存在（件数はランナーの出力が正）
```

**落ちたときに直すのは実装であって条件ではない。** `tests/run.sh` は凍結した合格条件で、
生成側の都合で書き換えない。

## 教訓（最大10行・超えたら統合してから追記）

- 可視化は「見た目が出た」で完了にできてしまう。**外部 CDN 1本**と**絶対パス1行**は目視で落ちるので、
  出したら必ず lint を通す（生成スクリプトは書く前に通す）
- 逆に **lint が通っても「読める1枚」にはならない**。lint は対応づけが正しいかを見ていない。**開いて見るまで完了にしない**
- **100 KB の HTML をモデルに1回で書かせない。** 入力集めは1〜2分で済むのに、書く段で 15〜45 分止まった（headless 4回）。
  決定論にできる部分は決定論に。モデルが書くのは判断（対応づけ）だけ
- 押せるものを足したら、**Tab で辿れるかを確かめる**。`href` の無い `<a>` はマウスでしか動かない
- `<pre>` の中で行を `<span>` で包むと、改行が二重になる。`pre` を `white-space: normal`、行だけを `pre` にする。**実描画でしか出ない**
