# harness-visualize — 処理1つを1枚の HTML にする

**これは処理であって工程ではない。** `目的を考える → … → 評価する →（改善する）` の連鎖には入らない。
`設計.md` を持つハーネスなら、**処理ごとに・いつでも**単独で呼べる。標準は〈評価する〉の直後。

**処理**＝ハーネスが持つ独立したワークフロー。**工程**＝その処理の中身。
可視化するのは**処理1つ分**で、複数の処理を1枚に混ぜない。

## やらないこと（ここが濁ると役割が壊れる）

- **判定しない。** GO / NO-GO も合否も書かない。判定は `harness-evaluator` の仕事。
  評価結果があるなら**転記するだけ**で、可視化側で採点し直さない
  （判定を持たせると、生成側が自分の合格線を描くことになる）
- **直さない。** ズレを見つけても直さない。直すのは `harness-improve`
- **図を書き換えない。** 読むだけ。`update_diagram` はこのスキルの許可ツールに無い
- **推測で埋めない。** 入力に無いものは「無し」と描く

## 入力（物差しは `docs/harness/<ハーネス名>/` のファイルだけ）

| 入力 | 出所 | 無いとき |
|---|---|---|
| 設計 | 索引 `docs/harness/<ハーネス名>/設計.md` と、描く処理の `処理/<処理名>/` | **これが無ければ実行しない。**止めてオーナーへ報告する |
| 図 | `処理/<処理名>/図.md` が指す DrillSpark（`get_project` / `get_diagram`）、または渡された `.mmd` | 「図 無し」と描き、工程は設計の記述から並べる。**ただし下を読む** |
| 実測 | `処理/<処理名>/実装.md`／`評価/<日付>.md`／**明示的に渡された記録ファイル** | 全工程を `設計のみ` と描き、そう明記する |
| 実装先 | `処理/<処理名>/実装.md` の**実物**を優先し、無ければ `合格条件.md` の成果物一覧。工程がどのファイルのどこになったか | その工程を `未記録` と描く |

**「図 無し」と「図が取れない」を混同しない。** `設計.md` が DrillSpark のプロジェクトを参照しているのに
`mcp__drillspark__*` が使えないなら、それは**図が無いのではなく繋がっていない**。
`設計.md` に図の参照があるときは `mcp__drillspark__list_projects()` を1回流して確かめ、
繋がらなければ**止めて案内する** → [`reference/drillspark-setup.md`](../../reference/drillspark-setup.md)。
黙って「図 無し」と描くと、**在る図を無いことにした1枚**が残り、次の人はそれを現状として読む。

**実測ファイルのパスを決め打ちしない。** `実行記録.md` のような名前は実行役が発明したもので、
`reference/設計.md.template` は定義していない。渡されたものを読む。
**渡されなければ聞かずに `設計のみ` で描く**（人間の介入点を増やさない。
承認を連打させる設計は承認そのものを無力化する）。

**止まるのは `設計.md` が無いときだけ**。物差しが無ければ描けるものが無い。

**設計側のファイルに無いものは描かない。**〈評価する〉と同じ物差しにしておかないと、
可視化だけが独自の事実を持ち始める。

## 手順

1. **入力を集める。** 上の表の3つ。どれが手に入り、どれが無いかを先に確定させる。
   **`設計.md` が無ければここで止めてオーナーへ報告する**
2. **構造を決定論で取り出す。** 図からノードID・形状・ラベル・レーン・エッジを機械的に拾う。
   LLM の読解で数え直さない。取れないもの（ループ上限・エスカレーション先）だけ備考と設計から読む
3. **実測と実装先を工程へ突き合わせる。** ノード単位で `通った` / `止まった` / `設計のみ` の3値にする。
   **実測が無い工程を `通った` にしない。**「記録が無い」と「通らなかった」は違うので、
   どちらも `設計のみ` に寄せて、記録が無い旨を書く。
   あわせて**実装先（ファイル＋箇所）を `処理/<処理名>/実装.md` から転記する**。
   **実ファイルを読んで埋め直さない** — 読んで書くと、可視化が設計側と違う事実を持ち始める。
   （**全文の引用のために読むのは可**。禁じているのは「対応づけを実ファイルから起こすこと」で、
   そのまま貼る引用ではない）
   `設計.md` に無ければ `未記録`。**`未記録` と「対応物が無い（`—`）」を混ぜない**
4. **HTML を組み立てる。** 契約は次節。`docs/harness/<ハーネス名>/可視化/<日付>.html` に書く。
   **同じ日に2回目を出すときは上書きしない。** `<日付>-2.html` のように連番を足す。
   「既存物を書き換えない」ことが、この処理に承認ゲートを置かなくてよい根拠になっている
5. **lint を走らせる。**

   ```bash
   node "$CLAUDE_PLUGIN_ROOT/scripts/harness-view-lint.js" docs/harness/<名>/可視化/<日付>.html
   # exit 0 = 合格 / 2 = 違反あり / 1 = 実行エラー
   ```

   通らなければ**直すのは HTML のほう**。**上限2回**で、それでも通らなければ
   **止めてオーナーへ報告する**（何がどう落ちたかを添える）。直し続けない
6. **読み戻す。** 書いたファイルを開き直して中身を確認する。成功メッセージを完了根拠にしない

## 出力 HTML の契約（lint が見る）

| | |
|---|---|
| 置き場 | `docs/harness/<ハーネス名>/可視化/<日付>.html` |
| 形 | **1ファイル完結。** CSS / JS はインライン、画像は `data:` URI。**外部読み込みゼロ**（CDN も不可） |
| ノード注釈 | 工程・ノードの要素に `data-node-id="2_1"`（数値ID形式・重複なし） |
| 節 | `data-section` を7つ: `目的` `処理一覧` `工程` `介入点` `合格条件` `成果物` `未完` |
| 図 | Mermaid 原文を `<pre class="mermaid">` に置く（**`<details>` に畳んでよい**。下記） |
| 状態 | `設計のみ` / `通った` / `止まった` の3値 |

**`data-node-id` はページ内で一意。** 同じノードを2箇所に書けないので、
**節を増やして同じノードを再掲する形にはできない**。ノードごとの情報は
「そのノードが1回だけ出てくる表」に**列として足す**。
ファイル単位の節（下記の「実ファイル」）はノードIDを持たないので、これに当たらない。

### 画面の作り（lint は見ない。だが必ずやる）

lint が見るのは上の表だけで、以下は**通ったことが根拠にならない**。それでも外すと1枚の価値が落ちる。

- **図はインライン SVG で描く。** `<pre class="mermaid">` はブラウザで開いてもただのテキストなので、
  **図として読めない**。外部ライブラリは禁止なので、BPMN の形（角丸＝terminal / 角＝process /
  ひし形＝decision / 円柱＝data store / 底が波＝document）を**自分で SVG に描く**。
  状態の3値は**枠線**に乗せる（色＋破線）。凡例を「枠の色＝状態」「形＝種別」の2群に分けて添える
  — 状態と記法を1つの凡例に混ぜると、読み手は「緑の矢印」を探して見つけられない
- **Mermaid 原文は捨てず、`<details>` に畳む。** SVG は手で描いたものなので**原文が正**。
  ズレたときの突き合わせ先と、ノード記法の出所が要る
- **決定論で作った表を必ず併記する。** SVG が壊れても表があれば情報は落ちない
- **表に実装先の列を足す**（ファイル／箇所／転記元）。これが「工程 → 実設定」を辿る本体
- **`実ファイル` の節を足し、登場したファイルの全文を `<details>` に畳んで埋め込む。**
  リンクにしない — 1ファイル完結なので、リンクは渡した先で切れる。
  **埋め込むと私的情報チェックが本文にも効く**。実ファイルに絶対パスや UUID があれば
  この1枚は落ちる。これは不便ではなく、**渡せない1枚になったことがその場で分かる**という意味
- **表のファイル／箇所から、その全文の該当行へ飛べるようにする**（インライン JS）。
  `<a href="#…">` を付けてキーボードからも到達できるようにする。
  マウス専用にすると Tab で辿れず、読み上げにもリンクとして出ない

**本文中のリンクは通る。** 出典 URL を `<a href="https://…">` で残してよい。
lint が見るのは**読み込み位置**（`link href` / `src` / `url()` / `@import`）だけ。

**節は中身が無くても出す。** 「無し」と書く。書かないのと「無い」と書いてあるのは違う。

**私的情報を入れない。** 絶対パス・UUID・メールアドレス。lint が落とすが、
落ちてから消すより、`設計.md` から転記する時点で相対パスに直しておくほうが速い。

## 合格条件

このスキル自身の合格条件は、プラグイン同梱の `tests/ok-view-*.html` `tests/ng-view-*.html` に凍結してある。
各サンプルは**期待するコードと件数**を `expect:` 行に持ち、ランナーが**終了コードだけでなくそれも照合する**。

```bash
bash "$CLAUDE_PLUGIN_ROOT/tests/run.sh"   # lint の期待挙動 ＋ 同梱ファイルの存在（件数はランナーの出力が正）
```

**落ちたときに直すのは実装であって条件ではない。** 条件を動かすときは
`harness-improve` の経路C（評価基準の変更承認ゲート）を通す。

## 教訓（最大10行・超えたら統合してから追記）

- 可視化は「見た目が出た」で完了にできてしまう。**外部 CDN 1本**と**絶対パス1行**は目視で落ちるので、
  出したら必ず lint を通す
- 逆に **lint が通っても「読める1枚」にはならない**。lint は図が読めるかを見ていないので、
  `<pre class="mermaid">` を貼っただけの exit 0 が作れてしまう。**開いて見るまで完了にしない**
- 押せるものを足したら、**Tab で辿れるかを確かめる**。`href` の無い `<a>` は
  マウスでしか動かず、それは目で見ても分からない
