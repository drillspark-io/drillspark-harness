# CodexからDrillSparkに接続する

## 未接続時の案内

この文書を実際に読み、利用者の環境に合う具体的な接続操作を会話内に提示する。
手順ファイルのリンクや「接続後に再開します」だけで終了しない。
まず「スキルは読み込めています。DrillSparkに接続して、業務の棚卸しを始めましょう」と案内する。
既に済んだ登録や設定を繰り返させない。キーやトークンをチャットに貼るよう求めない。

## OAuthで接続する（優先）

このプラグインは .mcp.json に接続先を同梱している。APIキーの発行・環境変数の設定から始めない。
本番の公開メタデータはOAuth（CIMD / DCR / PKCE）に対応している。
Codexでの認可からツール実行までの通し確認は別途必要であり、対応宣言だけで接続成功と扱わない。

1. 未登録なら [DrillSparkに登録](https://drillspark.io/?utm_source=github&utm_medium=referral&utm_campaign=drillspark_harness&utm_content=codex_setup)。
2. Codexのプラグイン詳細またはMCP設定で、このプラグインのDrillSpark接続を確認し、
   表示された接続・ログイン操作からブラウザ認証へ進む。
   実際のホストに表示された操作を使い、存在しないボタン名や自動起動を断定しない。
3. 利用者がブラウザでDrillSparkにログインし、要求された権限を確認して許可する。
   許可操作をエージェントが代行しない。
4. 新しい会話で「DrillSparkのプロジェクト一覧を見せて」と依頼する。
   ツールが現れなければアプリを再起動する。CLIでは /mcp でも接続状態を確認できる。

プラグイン側の接続操作が使えず、手動のMCP追加を希望する場合は次を案内する。
既存の同名サーバーを確認してから追加し、重複した接続を黙って作らない。
これはユーザー設定のサーバーに対するコマンドであり、プラグイン内のサーバー名を推測して渡さない。

```sh
codex mcp add drillspark --url https://drillspark.io/api/mcp/mcp
codex mcp login drillspark
```

認証に失敗したら確認できたエラーを伝え、原因に応じて対処する。すぐにAPIキー発行を要求しない。
Codexの仕様は [公式MCPドキュメント](https://learn.chatgpt.com/ja-JP/docs/extend/mcp) を参照する。

## APIキーで接続する（代替）

OAuthを使えない場合や利用者がAPIキーを希望した場合の手順。
[DrillSpark公式MCPガイド](https://drillspark.io/ja/docs/mcp) のCodex画面設定に沿って、
次の手順と表を会話内に表示する。

1. [ダッシュボード](https://drillspark.io/dashboard)右上のアバター →「APIキー」でキーを生成する。
   作図には読み取り・書き込み権限を選ぶ。キーは一度しか表示されないため利用者の手元で保管する。
2. Codexの「カスタム MCP に接続する」で以下を設定する。

| 項目 | 入力内容 |
| --- | --- |
| 名前 | drillspark |
| 接続方式 | ストリーミング可能なHTTP |
| URL | https://drillspark.io/api/mcp/mcp |
| Bearerトークン環境変数 | 空欄 |
| ヘッダー名 | Authorization |
| ヘッダー値 | Bearer の後ろに半角スペースとAPIキー |
| 環境変数からのヘッダー | 追加しない |

3. 保存し、新しい会話でプロジェクト一覧を取得する。キーは利用者自身が設定画面へ入力する。
   同梱のOAuth接続とは別設定になるため、どちらで接続を確認したかを区別する。

CLIで環境変数管理を希望する場合だけ、キーをDRILLSPARK_API_KEYに設定してCodexを起動し、
ユーザー設定 ~/.codex/config.toml に以下を追加する方法を案内する。既存設定と重複させない。

```toml
[mcp_servers.drillspark]
url = "https://drillspark.io/api/mcp/mcp"
bearer_token_env_var = "DRILLSPARK_API_KEY"
```

キーをコマンド履歴・チャット・Gitへ残さない。秘密値入りの設定ファイルを共有しない。
設定支援を依頼されていれば、既存設定を確認して秘密値を含まない設定の追記まで支援する。

## 接続確認と再開

利用可能なDrillSparkツールを発見し、list_projectsを読み取りで1回実行して確認する。
ツール未読込だけでは認証失敗と断定しない。認証・ネットワーク・ツール未読込を区別し、
確認できたエラーと次の操作を伝える。存在しない接続成功や利用権限を報告しない。
認証が必要な間は、図を作ったふりで後続工程へ進まない。
接続できたら利用者が依頼していた工程から再開し、回答済みの業務情報を聞き直さない。

MCP接続とhookの信頼は別。/hooks でこのプラグインの定義を確認・信頼する。
定義が変わった際も再確認し、利用者が信頼した記録をプログラムから偽造しない。
