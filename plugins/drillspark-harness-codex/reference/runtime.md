# Codex 実行規約

この配布物は Codex で実行し、初版の設定生成先も Codex。環境と生成先を設計.mdに別々に記録する。
異なる生成先を明示された場合は未対応と説明し、黙って置き換えない。

## 共通の入口

1. このファイルと [workflow-contract.md](workflow-contract.md) を読む。
2. スキル自身の絶対パスから2階層上がプラグインルート。スクリプトはその絶対パスで呼ぶ。
   hook 内では PLUGIN_ROOT が利用可能。通常のシェルにその環境変数があると仮定しない。
3. 利用可能なDrillSpark MCPツールを発見し、list_projectsを読み取りで1回呼ぶ。
   ツールが見つからない・接続できない場合は [drillspark-setup.md](drillspark-setup.md) を実際に読み、
   その場で登録リンク、OAuth接続の操作、再開方法を会話内に提示する。APIキー方式は代替手段として案内する。
   手順ファイルへのリンクや「接続後に再開します」だけで終えない。既に済んだ設定は繰り返させず、
   未完了の接続設定を支援する。接続確認が済むまで後続工程へ進まず、存在しないツール名を生成しない。
4. 既存成果物を読み、対象と承認済み工程を確認して再開する。

## 操作と承認

- ファイル変更は apply_patch。保護対象をシェルのリダイレクトやスクリプトで更新しない。
  可視化HTMLのみ、書込前ガードを内蔵する同梱harness-view-build.jsで生成する。
- ファイル読取/検索は提供されたシェル等を使う。Claude固有のRead/Write/Edit/ToolSearch/AskUserQuestionを呼び出さない。
- 利用者への問いは利用できる質問UI、なければ普通の質問で提示する。
  承認が必要なら応答まで依存する作業を止める。選択肢の初期値、無回答、時間経過を承認にしない。
- プラグイン導入は、図の作成や利用者が依頼した作業の範囲を超える公開・送信の承認ではない。
- フックの定義を作っただけでは有効にならない。/hooks で利用者が現在の定義を信頼したことを確認する。
  信頼回避オプションやガード無効化を自動で使わない。

## 独立したレビュー

レビューを要する工程では、Codexの別サブエージェントを起動する。
役割は `agents/<role>.md` の同梱本文を使い、絶対パスと対象、入力の場所だけを渡す。
親の合格結論を渡さない。レビュー側は同梱の基準を毎回読み、MCPから図を独自取得する。
対応する role は harness-design-reviewer / harness-asis-reviewer / harness-evaluator /
process-expert / process-improve-reviewer。プラグイン内のagentsディレクトリの自動登録を前提にしない。
サブエージェントが利用不能なら独立レビュー未実施として記録し、自己評価で代替して完了扱いにしない。
ファイルやMCPへ書き込ませない。評価で必要なコマンド実行は対象のテスト用領域と承認範囲に限る。
ローカルread-only sandboxがMCPの書き込みも防ぐとはみなさない。公開/外部書込権限を評価のために広げない。

## ガードの範囲

hooks/hooks.json は codex-guard.js を呼び、完成内容をClaude版と共通の3検査へ渡す。
追加/更新は検査、保護対象の削除/移動は拒否。曖昧な文脈、重複パスは正確なパッチに直す。
業務一覧と依存する表は別パッチにする。全ファイルを検査してから本体が適用する。
この仕組みは任意のシェルプログラムを隔離するサンドボックスではない。実体の変更と検査の間の
同時更新まで保証しない。評価時には実際のホストでフック発火も確認する。

## 配布物の検査と実機確認

`node <plugin-root>/scripts/check-codex-package.js <plugin-root>` は構造だけを検査する。
ファイルがあることは登録の証拠にしない。新規セッションでスキルの発見、/mcp、/hooks、
独立レビューの起動を確認し、実際に観測した範囲を記録する。
危険な本番操作を試し打ちしてガードを確認しない。テスト用ファイルとstdinのhook入力で検査する。
