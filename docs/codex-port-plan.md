# Codex 対応 — 実装と検証の記録

2026-09-06。対象: 同一リポジトリで Claude Code 版を維持し、Codex 版を別インストール可能にする。
公開・インストールの実施はソース実装と区別する。実機で通していないものを「対応確認済み」としない。

## 合格条件（実装より先に固定）

| ID | 合格条件 | 確認方法 |
|---|---|---|
| C1 | Claude 版の既存正常・異常系が維持される | tests/run.sh |
| C2 | Codex の追加・更新・削除・移動・複数ファイル編集で保護対象を検査する | 実ファイルを使う hook 入力テスト、正常編集も通す |
| C3 | 凍結済み条件の行変更・削除、版を上げない追加を止める | 既存凍結ファイルへの patch 入力 |
| C4 | 既存可視化の不正な上書きと上限超過、無効な業務表を止める | 共通 fixtures を使い完成内容を検査 |
| C5 | 6スキル・5レビュー/専門家の指示・共通資料・スクリプトが配布物だけで解決する | パッケージを移動して参照/実行検査 |
| C6 | 再生成が同一結果で、更新漏れをCIで検出する | build --check |
| C7 | Codex用設定を生成し、既存設定と人間の承認点を維持する | 対応表、設定パーサー、統合 fixture |
| C8 | 新規セッションで導入→MCP接続→作図→レビューを通す | 人間立会いの実機確認。未実施なら未検証 |
| C9 | 生成されたCodex設定でタスクを実行し、拒否・再開を確認する | 人間立会いの実機確認。未実施なら未検証 |

## 分割

1. 対応表・この合格条件。
2. 共通の手順/基準/スクリプトから配布物を生成。環境依存の入口・設定対応は別定義。
3. Codexガードとテスト。
4. process-improve / process-improve-view。
5. harness-implement / harness-compose / harness-improve / harness-visualize。
6. CI、導入ドキュメント、実機確認、告知の計測。

## 設計上の境界

- 実行環境と生成先を区別し、初版は同一環境向け生成だけを扱う。
- プラグインの独立レビュー役は同梱指示を別コンテキストへ渡して起動する。
  プラグイン内の agents/ が自動登録されるという未確認の前提を置かない。
- Codex hooks は利用者の信頼操作が必要。自動承認や信頼回避を導入に含めない。
- パッチの曖昧な照合を推測しない。対応外は適用前に止め、正確な文脈で再提示する。
- シェル文字列の検査は完全なサンドボックスではない。別スクリプト内部の任意の書き込み、
  同時変更、OS権限まで保証しない。権限設定と実機検証を別に扱う。
- MCPの閲覧専用制御とローカル read-only sandbox は別。レビュー役は読み取りツールだけを使う。
- 既存の業務フロー・評価基準を保ち、Codex固有の設定・権限の意味を単語置換で捏造しない。
